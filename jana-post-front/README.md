# Jana Address — интерфейс

Фронтенд кейса **Jana Address** (хакатон Jana Post × Terricon Valley): загрузить файл с адресами,
посмотреть разбор, вручную поправить неуверенные записи и выгрузить результат.

Стек: React 19 + Vite, обычный CSS, Leaflet для мини-карты. Никаких внешних CDN и шрифтов —
интерфейс работает без интернета (на финальном прогоне сеть отключена).

## Запуск для разработки

```bash
npm install
cp .env.example .env      # VITE_API_MOCK=true — демо-разбор прямо в браузере
npm run dev
```

- `VITE_API_MOCK=true` — ответы генерирует демо-парсер `src/api/mockParser.js`. Это **не** решение
  задачи, а заглушка, чтобы интерфейс жил без бэкенда. В шапке горит плашка «демо-режим».
- `VITE_API_MOCK=false` — запросы идут на `/api/v1`, Vite проксирует их на `API_PROXY_TARGET`
  (по умолчанию `http://localhost:8000`).
- `VITE_ALLOW_ONLINE_GEOCODER=false` — точка для открытой карточки берётся только из локального
  `/api/v1/geocode`. Nominatim/Overpass не вызываются. Значение `true` включает онлайн-геокодер
  как резервный вариант, если локальный геокодер не нашёл точку.

## Офлайн-карта

Без интернета карта переключается на собственные векторные тайлы из OpenStreetMap
(сборка [Protomaps](https://protomaps.com), формат PMTiles, отрисовка — `protomaps-leaflet` поверх Leaflet):

| Файл | Что внутри | Размер |
|---|---|---|
| `public/tiles/kz-base.pmtiles` | весь мир до z5 + Казахстан до z10 | ~109 МБ |
| `public/tiles/kz-cities.pmtiles` | 23 крупных города (`offline-map/cities.geojson`) до z15 — все улицы и дома | ~99 МБ |

Файлы не хранятся в git. Для разработки скачать один раз (нужен интернет):

```bash
npm run map:fetch
```

В Docker-образ карта попадает сама: стадия `maps` в `Dockerfile` запускает тот же скрипт
`offline-map/fetch.sh`, nginx отдаёт файлы из `/tiles/`.

Как работает переключение: если онлайн-провайдер тайлов не ответил за 6 секунд или браузер
офлайн (`navigator.onLine === false`), карта сразу берёт «Офлайн-карту» (светлую или тёмную —
по теме). Её можно выбрать и вручную в переключателе стилей. Точку открытой карточки фронт
получает у локального геокодера `/api/v1/geocode` — Nominatim/Overpass по умолчанию не вызываются.

### Локальный геокодер

Для открытой карточки `Workspace` вызывает `POST /api/v1/geocode` и передаёт координаты в
`CustomMap` как `focusPoint`. Запись при этом не мутируется: `lat`/`lng`/`precision` не попадают
в `records` и в экспорт. Ответы кэшируются в памяти по `record.id`, включая `null`, поэтому
повторное открытие записи не дёргает API. При быстром переключении предыдущий запрос отменяется
через `AbortController`.

Масштаб карты зависит от `precision` из ответа:

| `precision` | Подпись | Zoom |
|---|---|---|
| `house` | «Точный дом» | 17 |
| `house_approx` | «Несколько домов — приблизительно» | 16 |
| `street` | «Улица — приблизительно» | 15 |
| `living_area` | «Микрорайон — приблизительно» | 14 |
| `district` | «Район — приблизительно» | 13 |
| `city` | «Город — приблизительно» | 11 |
| `province` | «Область — приблизительно» | 8 |
| `null` | «Точка не найдена» | текущий вид |

Если локальный геокодер вернул `null`, карта показывает «Точка не найдена» и не делает сетевых
запросов. Онлайн-фоллбэк (Nominatim + Overpass) включается только флагом
`VITE_ALLOW_ONLINE_GEOCODER=true`; код провайдеров остаётся в `geocodeProviders.js`.

## Docker

Образ: сборка Vite → nginx, который отдаёт статику и проксирует `/api/*` на бэкенд.

```bash
docker build -t jana-address-web .
docker run -p 8080:80 -e API_UPSTREAM=http://host.docker.internal:8000 jana-address-web
```

Кусок для общего `docker-compose.yml`:

```yaml
services:
  web:
    build: ./jana-post-front
    container_name: jana-address-web
    ports:
      - "8080:80"
    environment:
      API_UPSTREAM: http://api:8000   # имя сервиса бэкенда в compose
    depends_on:
      api:
        condition: service_healthy
```

nginx резолвит адрес бэкенда при каждом запросе, поэтому фронт стартует, даже если `api` ещё поднимается.

Флаг `VITE_ALLOW_ONLINE_GEOCODER` вшивается в статику на этапе сборки. Чтобы включить онлайн-фоллбэк
в образе, передайте build-arg:

```bash
docker build --build-arg VITE_ALLOW_ONLINE_GEOCODER=true -t jana-address-web .
```

> Windows: если сборка падает с `set: line 2: illegal option -`, значит
> `offline-map/fetch.sh` получил CRLF. В корневом `.gitattributes` зафиксирован
> LF, а Dockerfile очищает `\r` перед запуском. После `git pull` пересоберите:
> `docker compose -f docker-compose.yml -f docker-compose.build.yml build --no-cache web`.

## Контракт с бэкендом

### `POST /api/v1/parse/batch`

Запрос — массив записей в формате `sample_input.json`:

```json
[{ "id": "rec_00417", "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70" }]
```

Ответ — массив в формате `sample_output.json` (можно также `{ "results": [...] }`):

```json
[{
  "id": "rec_00417",
  "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70",
  "province": "Алматы", "city": "Алматы", "district": "Ауэзовский", "living_area": null,
  "street_type": "микрорайон", "street_name": "Аксай 3а", "house": "59",
  "apartment": "70", "entrance": null, "floor": null, "landmark": null,
  "confidence": 0.91
}]
```

Фронт отправляет записи пачками по 500. Если на какой-то `id` ответа нет, фронт подставляет
пустую запись с `confidence: 0` — пропусков в выгрузке не будет.

### `POST /api/v1/geocode`

Геокодинг одной записи — по готовой строке или по уже разобранным полям:

```json
{ "id": "rec_001", "raw_address": "Алматы, Абая 47" }
```

```json
{ "id": "rec_001", "city": "Алматы", "street_name": "Абая", "house": "47" }
```

Ответ всегда со статусом 200. Если точки нет — координаты и `precision` равны `null`:

```json
{
  "id": "rec_001",
  "lat": 43.2424586,
  "lon": 76.9423147,
  "precision": "house",
  "source": "osm"
}
```

`precision`: `house`, `house_approx`, `street`, `living_area`, `district`, `city`, `province`
или `null`. Фронт кэширует ответ по `id` и не сохраняет координаты в записи.

### `POST /api/v1/geocode/batch`

Опциональный пакетный геокодинг для prefetch: принимает массив записей или `{ "items": [...] }`,
возвращает массив в том же порядке. Заголовки ответа: `X-Records`, `X-Elapsed-Ms`.

### Необязательные поля (интерфейс использует их, если они есть)

| Поле | Зачем |
|---|---|
| `sources: { "district": "reference", "living_area": "text", ... }` | Точно показать, какие поля подняты из справочника, а какие взяты из строки. Без него фронт угадывает: если значения района/ЖК нет в исходной строке, считаем, что оно из справочника. |

В выгрузку эти поля не попадают — экспорт строго в формате `sample_output.json` (14 полей ТЗ,
без `lat`/`lng`/`precision`).

## Как устроен интерфейс

Только то, что требует ТЗ: загрузить файл → посмотреть разбор → поправить неуверенные → скачать.
Визуально — в духе сервисов Яндекса: белые блоки на сером фоне, короткие инструкции из шагов,
основной цвет — зелёный Jana Post. Карта на весь экран, слева панель (на телефоне — шторка снизу).

1. **Главная** — бенто-сетка (как в Яндекс Практикуме): зелёный блок с главным действием
   (выбрать файл, перетащить, вставить текстом), две плитки-шага с иллюстрациями из иконок и
   тёмная колонка «Что получится» — поля ответа по ТЗ.
2. **Список** — над ним закрываемая подсказка «Как проверить разбор»; в строке — исходный адрес, под ней разбор одной строкой, справа уверенность
   (красным — ниже 70%). Вкладки «Все / Неуверенные», поиск.
3. **Карточка адреса** — блоки «Исходная строка», «Адрес», «Для курьера» — все поля ответа по ТЗ. При фокусе на поле в исходной строке
   подсвечивается фрагмент, из которого оно взято. «Сохранить» отмечает запись проверенной
   (`confidence: 1`) и открывает следующую. `Esc` — назад к списку.
4. **Карта** (`components/CustomMap`) — по умолчанию CARTO Voyager, остальные стили (в т.ч. Яндекс Карты) в переключателе.
   Для открытого адреса берёт точку из `/api/v1/geocode`, ставит маркер и выбирает zoom по `precision`;
   если точки нет — пишет «Точка не найдена». Онлайн-геокодер используется только при
   `VITE_ALLOW_ONLINE_GEOCODER=true`.
5. **Скачать JSON** — результат строго в формате `sample_output.json`.

Сессия хранится в `localStorage` и переживает перезагрузку страницы.

## Структура

| Путь | Что внутри |
|---|---|
| `src/App.jsx` | Шапка и переключение «загрузка ↔ проверка» |
| `src/hooks/useReviewSession.js` | Состояние сессии: разбор, правки, откат, сохранение в localStorage |
| `src/api/client.js` | Пакетный вызов `/api/v1/parse/batch`, геокодинг `/api/v1/geocode`, нормализация ответа |
| `src/api/mockParser.js` | Демо-парсер для режима без бэкенда |
| `src/address/fields.js` | Список полей, подписи, типы улиц, порог по умолчанию |
| `src/address/records.js` | Импорт/экспорт, источник поля, подсветка в исходной строке |
| `src/components/Upload/` | Экран загрузки |
| `src/components/Review/` | Экран работы: карта + панель со списком и карточкой адреса |
| `src/components/CustomMap/` | Движки карты (Leaflet/Яндекс), тайлы, локальный `focusPoint`; Nominatim/Overpass — только при `VITE_ALLOW_ONLINE_GEOCODER=true` |
| `nginx/`, `Dockerfile` | Продакшен-образ |
